Feature Delivery

Specific Meetings with Invite-Only RSVP

Cal.com additive feature implementation (minimal core coupling)

Goal: fixed date/time meetings + invitees + yes/no RSVP (Google Calendar/iCal style)

Constraint: keep upgrades easy by minimizing core code changes

Approach: feature-owned domain + thin booking bridge

Architecture Decisions

  • Isolated domain (modeled after Polls) instead of changing core booking semantics
  • RSVP state stored in feature tables, not core Booking/Attendee
  • Still creates one real Cal.com booking via RegularBookingService.createBooking
  • Public RSVP links are tokenized: /meeting/[uid]?token=...
  • Organizer UX integrated as an Event Type tab

Phase 1 Scope Choice

Track RSVP internally; defer provider-calendar decline sync.

Backend Implementation

Repository: packages/features/specific-meetings/repositories/SpecificMeetingRepository.ts

Service: packages/features/specific-meetings/services/SpecificMeetingService.ts

  • Create specific meeting + validate participants/time window
  • Create linked booking (idempotency key: specific-meeting:${uid})
  • Attach booking to specific meeting
  • Organizer retrieval/list with per-invitee response URLs
  • Public invitee lookup by uid+token
  • RSVP mutation (accepted/declined)
  • Cancel mutation: cancel booking via handleCancelBooking + mark meeting cancelled
